# Как самому менять экономику Delsk

Текущий профиль пакета3 — `presentation-economy-v4`: `world.rules.handling` personal/worker4/4 объёма за тик; `world.resources[]` задаёт private/public stock/regen/цены/lease. Частные200/10 за120, общие50/2 за120; buy10000/lease1000minor за1200ticks — параметры пилота. Профиль не меняет координаты, public/private или initial owner из сценария. Три карты и сохранённые config используют явную географию. [Руководство](PHYSICAL_AUTOMATION.md). Политика600/остановленная стадия и зарплата20/шаг5 прежние.

Пакет2 обновил id до presentation-economy-v3 и world.elections: periodTicks600/pauseForBallots=true. Зарплата20/шаг5 и прочий обычный баланс прежние. Старые сохранённые конфиги не заменяются. Безопасный Developer override wage exponent хранится отдельным аудитом; цена/объём/вместимость не переписываются. [Процедура](DEVELOPER_TOOLS.md).

Автор: Шелестов Максим Евгеньевич. Обновлено19.10.2026, пакет1.

Основной файл — **[config/economy.json](../config/economy.json)**. Это единый профиль с разделами `world` и `npc`. Три игровые карты используют его при создании новой партии. География остаётся в scenarios: экономический профиль не переносит лес, дорогу или столицу.

В JSON нельзя писать комментарии; сохраняйте запятые и кавычки. Неизвестные поля, дубликаты ключей, неверные типы и недопустимые значения дают ошибку. Молчаливой замены ошибочного файла настройками по умолчанию нет. Начните с копии рабочего файла и меняйте один фактор за опыт.

## Зарплата и «стоимость найма»

Отдельного разового тарифа за приём нового работника сейчас **нет**. Группа получает одну ставку; расходы рабочего шага пропорциональны числу занятых работников. При простое зарплата не списывается, люди уходят постепенно. Дополнительный сотрудник не вызывает автоматического процентного удорожания остальных. Боты могут повышать предлагаемую ставку, конкурируя за людей.

Имена оканчиваются на `Minor`, если величина денежная. **100 minor = 1 денежная единица**. Ставка25 — это0.25 за работника за оплачиваемый рабочий тик, а не25 рублей и не разовая плата. Обычный визуальный режим использует1 секунду активного времени на тик; headless считает те же тики быстрее реального времени.

| Что изменить | Поле в config/economy.json | Сейчас |
| --- | --- | --- |
| Шаг кнопок зарплаты человека «+ / −» | `world.rules.playerWageStepMinor` |5 =0.05 |
| Базовая предлагаемая ботами зарплата | `npc.baseWageMinor` |20 =0.20 |
| Насколько бот повышает ставку над конкурентом | `npc.wageRaiseMinor` |1 =0.01 |
| Верхняя ставка бота | `npc.maximumWageMinor` |50 =0.50 |
| Как часто бот пересматривает зарплату | `npc.wageReviewTicks` |60 тиков |
| Начальная ставка производства | `world.buildingTypes[].levels[].wageMinor` |20 |
| Начальная ставка добывающей техники | `world.equipmentTypes[].levels[].wageMinor` |20 |
| Начальная ставка экипажа грузовика | `world.logistics.wageMinor` |20 |
| Период кадрового пересчёта | `world.labor.stepTicks` |10 тиков |
| Задержка привлекательности новой ставки | `world.labor.salaryChangeDelayTicks` |20 тиков |
| Скорость постепенного перехода работников | `world.labor.mobilityNumerator / mobilityDenominator` |1/10 |
| Влияние зарплаты на привлекательность | `world.rules.wageAttractionExponent` |3, то есть зарплата³ |

Начальная ставка здания и политика её дальнейшего изменения — разные настройки. Например, чтобы исследовать повышение зарплат, измените `npc.baseWageMinor` с20 на40, максимум с50 на80, шаг с1 на5. Если нужны более высокие ставки уже при открытии предприятий, измените также `wageMinor` соответствующих уровней. Для сравнения одинаковой фиксированной ставки у ботов задайте одинаковые base/maximum; шаг0 запрещает повышение сверх конкурента, но сам по себе не отменяет установку базовой ставки.

Изменение кнопки «+» не меняет стоимость существующего персонала: оно меняет величину следующей отправляемой команды. Новая объявленная зарплата применяется по общим правилам задержек, а не переписыванием денег или численности из UI.

## Остальные разделы профиля

| Раздел | Что в нём находится |
| --- | --- |
| `world.startingCashMinor`, `personalInventoryCapacity` | Стартовые деньги и вместимость участников |
| `world.population`, `labor.growthPeriodTicks`, `growthPerPeriod` | Начальная численность и прирост населения |
| `world.plotPriceMinor`, `shopSitePriceMinor` | Цены обычного участка и общего места лавки |
| `world.rules.reservationFeeBasisPoints`, `landReservationTicks`, `maxActivePlotReservations` | Плата за бронь, её срок и общий лимит броней.1000 basis points =10%;0 — бесплатная бронь. Ограничение одной лавки действует отдельно |
| `world.harvestTicksPerUnit`, `moveTicksPerCell`, `tradeWindowTicks` | Длительности добычи, передвижения и торгового окна |
| `world.items[]` | ID товара, физический объём единицы и базовая цена |
| `world.recipes[]` | Вход/выход рецепта, длительность, полный/минимальный персонал и энергия |
| `world.buildingTypes[].levels[]` | Цена стройки/улучшения, материалы, вместимости, численность, ставка и производительность |
| `world.equipmentTypes[].levels[]` | Цена добывающей машины, объём/длительность цикла, хранилище и экипаж |
| `world.logistics` | Цена грузовика, грузоподъёмность, скорость, экипаж и зарплата. `upgrade:null` сохраняет отсутствие улучшения в обычном балансе; заданный объект включает каталог улучшения |
| `world.market` | Раунды аукциона, минимальное повышение, срок выдачи и штраф за невывоз |
| `world.delivery` | Сроки будущих поставок/предложений и процент штрафа/обеспечения |
| `world.capitalDemand` | Период спроса, стартовый бюджет, отношение спроса к выпуску, периоды волн, срок заказа и масштаб цены |
| `world.rules` | В том числе нижние/верхние границы общей и товарной ценовой волны, шума и веса товарного спроса |
| `world.elections` | Период выборов и базовый голос участника |
| `world.support` | Вместимость секции политической компенсации |
| `world.rules.city` | Три порога капитала/населения/действующих производств и `confirmationTicks`; одинаковое подтверждение повышения/понижения, без бонусов |
| `world.maxTicks` | Горизонт разрешённой партии/прогона; это не гарантия производительности или размера сохранения |
| `npc` | Запас денег, объём добычи/лота, базовая/максимальная зарплата/её шаг, оценка покупки/продажи, цена поддержки, интервалы решений и веса целей |

`basisPoints`:10000=100%,500=5%,12500=125%. В разных формулах округление задано правилами: плата за бронь округляется вверх до minor; штрафы имеют своё целочисленное округление. Самостоятельно править формулы C# для изменения этих процентов не нужно.

`terminal`/`tradingPoint` в экономическом профиле — шаблонные координаты; при применении берутся координаты выбранной карты. Не используйте их для перестановки столицы: меняйте географию сценария. В обычных картах общих мест лавок больше числа участников (сейчас5 на4); одно купленное или забронированное место на участника в сумме — правило игры, а не цена, обходящаяся настройкой лимита обычных броней. Исторические равные fixtures допустимы.

Текущий профиль — `presentation-economy-v2`, World14/Rules `household-management-1`. Сохранённые config/current wages не заменяются новым файлом профиля; World13 не мигрируется, старый versioned save path не перезаписывается. Средняя действующая ставка и обеспеченные вакансии считаются общим Core PublicEconomy; описание капитала/городских стадий и ограничения — [отчёт пакета1](IMPLEMENTATION_REPORT_PACKAGE1.md), ARCHITECTURE §34. Цены товаров в капитале фиксированы базовыми ценами профиля; текущая рыночная цена не повышает оценку запасов.

Поля `actorId`, `humanActorId`, `preferredInput` принадлежат составу участников, а не общему экономическому профилю; перекрывать их через `npc` запрещено. Два исторических коэффициента `harvestCoefficient`/`productionCoefficient` пока поддерживают только1; иное значение явно отклоняется. Для опытов меняйте реальные длительности/рецепты/характеристики техники. Legacy `scenarios/*-cycle.json` остаются самостоятельными регрессионными фикстурами: изменение их ожидаемой бухгалтерии не является настройкой обычной игры.

## Проверить и запустить

Команды PowerShell из корня Delsk. Нужны SDK10.0.401, для визуального клиента Godot.NET4.7.2.

```powershell
dotnet build Delsk.sln -c Release --nologo '-m:1'
dotnet src/Research.Runner/bin/Release/net10.0/Research.Runner.dll --script baseline --scenario scenarios/baseline-economy.json --economy config/economy.json --validate-only true
dotnet src/Research.Runner/bin/Release/net10.0/Research.Runner.dll --script baseline --scenario scenarios/baseline-economy.json --economy config/economy.json --seed 42 --ticks 1200 --profile true --output artifacts/my-economy-42
```

`--validate-only true` ничего не симулирует. Обычный baseline использует полный алгоритмический контроллер; LLM выключена. Для собственного профиля нулевой выпуск или отсутствие предприятий могут быть допустимым результатом опыта: проверяются инварианты, а не фиксированные целевые числа исторического baseline. Для второй карты замените scenario на `scenarios/presentation-map-two.json`. Если `--economy` не указан, runner читает самостоятельный сценарий как раньше; для опытов указывайте профиль явно.

```powershell
dotnet build src/Client.Godot/Delsk.Client.csproj -c Debug --nologo '-m:1'
godot --path src/Client.Godot
```

В обычном запуске из проекта обе карты читают `config/economy.json` с диска при создании партии, поэтому редактирование JSON не требует пересборки C#. Создайте **новую партию** через выбор карты. Технические режимы `--smoke`, «Политика» и «Рейс» сохраняют свои отдельные фикстуры. Для запуска с другой копией профиля:

```powershell
godot --path src/Client.Godot -- --economy D:/Experiments/economy-high-wages.json
```

Экспортированная сборка содержит встроенную копию профиля на момент сборки; собственный внешний файл передаётся тем же аргументом. Путь зависит от вашего компьютера. Промпт Cursor или Codex для изменения чисел не нужен.

## Сохранение, повтор и результаты

В начале партии профиль превращается в полностью разрешённую конфигурацию Core. Сохранение хранит её и реальные настройки контроллеров. Изменение файла на диске не переписывает загруженную партию. Поэтому `--economy` нельзя сочетать с `--load`/`--replay`: это создало бы другой эксперимент под видом продолжения.

В каталоге результата:

- `economy-profile.json` — точный профиль нового прогона; `scenario.json` — вся разрешённая конфигурация, включая карту.
- `manifest.json` — профиль ID, seed, версии правил/схемы, config hash и состояние контроллеров; `controllers.json` — их сохранённые параметры/память.
- `summary.json`, `metrics.csv`, `labor.csv`, `agents.csv` — деньги, товар, занятость и поведение.
- `commands.jsonl`, `events.jsonl`, `decisions.jsonl` — записанные действия и результаты для исследования; содержат исследовательские данные, не публичную проекцию игрока.
- `profile.json` — измерения времени тика и save/load. Headless-профиль не измеряет FPS Godot или скорость телефона.

Повтор без новой модели:

```powershell
dotnet src/Research.Runner/bin/Release/net10.0/Research.Runner.dll --script baseline --scenario artifacts/my-economy-42/scenario.json --replay artifacts/my-economy-42/commands.jsonl --ticks 1200 --output artifacts/my-economy-42-replay
py -3 scripts/verify_checkpoint_exports.py --world-only artifacts/my-economy-42 artifacts/my-economy-42-replay
```

Для настоящего продолжения используйте `--checkpoint FILE --checkpoint-at 350` при новом запуске, затем `--load FILE --ticks 1200`; `--profile true` не совмещается с checkpoint-at. Это разные проверки: replay повторяет команды, load восстанавливает состояние и память NPC.

## Несколько семян и сравнение A/B

Скопируйте профиль, измените `id` и нужный фактор. Например, создайте `config/economy-high-wages.json` для повышенных зарплат. Затем:

```powershell
py -3 scripts/run_economy_study.py --economy config/economy.json --economy config/economy-high-wages.json --seeds 42,43,44 --ticks 600 --output artifacts/wage-study-01
```

Скрипт делает точные копии входов и SHA-256, выполняет одинаковые семена для каждого профиля, сохраняет логи с timeout и создаёт `comparison.csv`/`study.json`. Python только запускает C# и читает выгрузки. Старый каталог результатов не перезаписывается: для нового опыта задайте другой output.

Сравнивайте парные результаты одинакового seed/горизонта, денежные расходы, выпуск, занятость и простои. Больше зарплата не гарантирует больше выпуска: персонал может перераспределиться, деньги закончиться, входной склад опустеть. Три семени — проверка процедуры, не научный вывод; для исследования используйте достаточную серию и заранее выбранную метрику. Реальные LLM-серии выполняются отдельно по RESEARCH_READINESS.md/LOCAL_MODEL_VALIDATION.md.

Сейчас вся исследовательская история сохраняется в памяти. Длинные партии становятся тяжелее; измеренные границы и ограничения — [отчёт P27](IMPLEMENTATION_REPORT_P27.md). Повышение `maxTicks` не снимает лимитов файла, памяти и целевого устройства.
