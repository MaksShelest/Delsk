# Исследование полной экономики H1

Автор: Шелестов Максим Евгеньевич.

Инструменты запускают действующий `Research.Runner` и читают его экспорты. Python
не принимает экономических решений за NPC и не рассчитывает альтернативную партию.
План условий: [study-plan.json](research/h1/study-plan.json). Статистические
определения: [analysis-plan.json](research/h1/analysis-plan.json).

## Подготовка

Из корня репозитория, с .NET SDK из `global.json` и Python 3.12:

```sh
python scripts/run_check.py --name h1-restore --timeout 180 -- dotnet restore src/Research.Runner/Research.Runner.csproj --locked-mode --disable-parallel -m:1
python scripts/run_check.py --name h1-build --timeout 180 -- dotnet build src/Research.Runner/Research.Runner.csproj -c Release --no-restore --disable-build-servers -m:1
python scripts/run_check.py --name h1-unit --timeout 60 -- python -m unittest discover -s tests/Research.Lab -v
```

Не пересобирать бинарники и не менять входы симуляции между частями одного
исследования. Их SHA-256 закрепляются в `study-inputs.json`; очередь дополнительно
проверяет профили и DLL перед каждой попыткой. Для другого кода нужен другой каталог.
Тяжёлые локальные проверки и прогоны выполнять последовательно.

## Матрица обычных партий

```sh
python scripts/study_economy_h1.py --output artifacts/h1-study --phase pilot --compress-turns
python scripts/study_economy_h1.py --output artifacts/h1-study --phase pairs --compress-turns
```

Это 90 пилотных партий (18 условий × 5 seeds) и 30 дополнительных партий с шестью
NPC. В выбранных сравнениях получается по десять независимых пар на карту.
Существующий `OrdinaryNewGame.Resolve` создаёт участников, позиции и G1-контроллеры
из профиля. `ordinaryNpcCount` — явный JSON/CLI режим лаборатории; старые пресеты
с явным `controllers` сохраняют прежний смысл. Выбор нового профиля сам по себе
не превращает legacy controller plan в обычную новую игру.

Для короткой собственной серии можно передать план
[ordinary-smoke.json](research/h1/ordinary-smoke.json) через существующий API/редактор
JSON лаборатории. В обычном режиме запрещены неоднозначные overrides состава,
явные старые controllers и игнорируемые факторы; смешанные планы отвергаются.

Очередь `lab/queue.json` сохраняет каждую попытку. SIGTERM/SIGINT ставят паузу после
текущего ограниченного прогона. Повтор команды переиспользует завершённые результаты;
`--retry-failed` явно создаёт новые попытки, сохраняя прежние ошибки. Одновременно
два процесса над одним каталогом запускать нельзя. `--compress-turns` после измерения
архивирует полный `decisions.jsonl` в gzip с проверкой исходного byte hash; это
специальный режим хранения исследования, а не новый формат обычного web-viewer.

## Длинные траектории и продолжение

```sh
python scripts/study_long_h1.py --output artifacts/h1-long-small --map small-river --segments 1 --compare-first-two
python scripts/study_long_h1.py --output artifacts/h1-long-small --map small-river --segments 1 --compare-first-two
python scripts/study_long_h1.py --output artifacts/h1-long-small --map small-river --compare-first-two
python scripts/study_long_h1.py --output artifacts/h1-long-large --map large-districts --compare-first-two
```

Первая и вторая команды — отдельные процессы с настоящим checkpoint/load.
`trajectory.json` хранит границы, проверки, SHA сохранения и незавершённые попытки.
После аварии или ошибки требуется диагностика и явный `--retry-failed`; неудачный
каталог не удаляется. Смена карты, инструмента, входов или DLL в той же траектории
отвергается. После второго сегмента проверяется точное совпадение с непрерывной
партией, включая частный экспорт денежных обязательств.

Исходный G1 профиль заканчивается на 5000 тиках. Длинная когорта отдельно увеличивает
**только** `maxTicks` разрешённого стартового сценария и `controller finalTick` до
126000 (35 активных часов). Это объявленное изменение горизонта планирования;
не следует смешивать её с обычной партией с прежним горизонтом. Старые профили,
сохранения и ограничения чтения 64/512 MiB не меняются. Каждый сегмент ограничен
900 секундами; после него выполняются учёт и проверка приватности.

`--progress true` у runner пишет лёгкий `run-progress.json`: фактический тик,
фазу, время процесса и RAM. Он не вызывает Core inspection и не записывает
исследовательские World frames. Последний heartbeat при аварии — нижняя граница
прогресса и наблюдавшейся памяти, а не обязательно окончательный пик.

## Повторный анализ

После остановки очереди либо её полного завершения:

```sh
python scripts/reanalyze_economy_h1.py --study artifacts/h1-study --output artifacts/h1-analysis-v1 --plots
```

Для SVG требуется matplotlib. Без `--plots` стандартной библиотеки Python достаточно.
Новый анализ получает отдельный каталог; исходная очередь и её ранние метрики
не переписываются. Сохраняются SHA скриптов, снимок протокола и byte hashes всех
исходных экспортов. Изменившаяся во время чтения очередь приводит к отказу.

Основная величина сравнения — медиана прироста капитала NPC внутри каждой партии,
по собственной оценке Core. Это одна наблюдаемая величина на seed, **не денежная
прибыль**. Сравнения показывают парные разности, median/IQR/min/max, точный sign test,
Holm по четырём заранее выбранным контрастам и bootstrap-интервал медианы. При
пропавшей партии пара остаётся неполной; отсутствующие производства/ступени
цензурируются, не заменяются нулём или временем окончания.

`full_economy_metrics.py` отдельно читает реальные оплаченные товарные сделки,
вознаграждения услуг, зарплаты, дорогу и капвложения. Пополнение escrow/возвраты
не являются доходом. `operatingAfterRoadDebtMinor` дополнительно вычитает остаток
счётов и целые ещё не выставленные дорожные начисления; оплаченная дорога повторно
не вычитается. Неизвестный денежный reason виден в отчёте и исключает сравнение
операционного результата. Денежный ledger каждого участника сверяется с балансом.
Покупные стройматериалы входят в оплаченные товарные затраты; их цена пока не
распределяется по конкретным строящимся активам. Это результат денежных поступлений
и затрат, а не бухгалтерская чистая прибыль отдельного предприятия.

Ресурсы, заполнение складов, traffic reasons и долги на последнем тике — снимки,
не средние за партию. Idle/Wait и неготовые работники — наблюдаемые samples, они
не доказывают отсутствия допустимого действия. HHI по предприятиям не является
HHI выпуска. Ненаблюдавшаяся окупаемость остаётся открытой: нет умножения одной
маржи на вымышленные будущие рейсы и нет бесплатной оценки личного труда.

Частный `personal-accounts.json` предназначен для локального исследователя и CI,
не передаётся в публичную карту или наблюдения NPC. Подготовленные F2 контрольные
заказы проверяются `check_economy_h1.py` отдельно от стартовой матрицы.
