# I6-C1.1 — контекстные действия и выбор карт

Автор: Шелестов Максим Евгеньевич.

Основа: `feat/economic-cycle-p00-p05`, `5c3511d` (merge PR #86). Отдельная ветка `feat/vnext-i6c11-context-map-menu`; PR остаётся Draft, без merge.

## Изменения

- Контекст содержит только местные действия. Глобальные разделы доступны через планшет. Перенос товаров открывает прежнюю форму с выбранными источником и получателем; общий `ManualTransferChoice` перенесён в Hosting без изменения правил.
- Внизу по центру — компактные горизонтальные команды и `⋯`. Сворачивание оставляет одну кнопку `⚡ N` справа внизу. `N` учитывает доступность и pending; ручной режим сохраняется после перемещения и пересборки HUD до новой партии/сеанса.
- Покупка использует актуальную цену модели. Прямых предложений не больше трёх; доступные модели получают приоритет, полный ассортимент открывается в локальном автосалоне. Сохраняются ключи, повторная проверка scope/payload, pending, AccessFor, RU/EN и shield.
- Главное меню: настройки партии слева, крупная карта справа; сложные параметры находятся в дополнительных настройках. Каталог состоит из двух светлых горизонтальных карточек. Предпросмотр рисует сплошную землю, реальные дороги, контуры площадок, ресурсы и объекты.
- Пользовательский каталог: только `compact-valley` и `second`. Первая рекомендуется по умолчанию. Вторую можно рассмотреть; новая ordinary-партия отключена, пока профиль не поддерживает современную экономику. `All`, старые JSON и разрешение ID сохранений сохранены.

## Сценарии и проверки

**17/17 целевых тестов, 104 native checks и 6 проверок переноса восьми кнопок прошли.** Сборка клиента: 0 ошибок/предупреждений; ordinary AssemblyAudit успешен. Финальные результаты и исходные отказы записаны в `verification/i6c11/verification.json`. Один объединённый оконный smoke: подготовленная «Малая долина», три обычных NPC; пустая клетка, ресурс/Stop, свой склад/форма переноса, сворачивание/счётчик при движении, цена/покупка/свой транспорт, меню/каталог, NPC/сложность, старое сохранение `first`. Клавиатура, мышь и synthetic touch; размеры 1100×720, 960×440 и дополнительный 800×360.

Проверяется ровно одна команда при повторном нажатии и одна фактическая покупка. Отдельно — устаревший payload, пауза, восстановление checkpoint и отсутствие Developer API в ordinary-пакете. Обязательные CI jobs/deadlines сохранены; исторические native-пробники адаптированы к новому каталогу и локальному контексту. Полные экономические прогоны и replay-матрицы локально не запускались. Первые ошибки пробника/компоновки/изоляции и timeout 180s сохранены; после исправлений повторялись затронутые проверки, лимиты не повышались.

## Ограничения

Linux, Godot .NET 4.7.2 / SDK 10.0.401, Mesa software GL; это не аппаратная приёмка Windows/Android. Деньги и склад подготовлены для UI-проверки, а не получены естественным прогрессом. Экономика, Core и игровая геометрия не менялись. Адаптация `second` остаётся I6-C2; следующие этапы не начинались. Результат передаётся для визуальной оценки пользователя.

Воспроизведение: `python scripts/check_i6c11_native.py --godot /path/to/Godot_v4.7.2-stable_mono_linux.x86_64 --output work/i6c11-check`. Нужен SDK 10.0.401; команда использует изолированный source stage и собственный Xorg.
