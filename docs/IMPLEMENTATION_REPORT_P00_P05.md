## Результат

Реализован проверяемый консольный экономический стенд. Один участник через общие команды добывает сырьё, физически переносит его к подготовленному предприятию, производит товар с оплатой числового штата и энергии, переносит продукт в терминал и продаёт столице после закрытия окна. Дополнительный сценарий начинает с нулевых денег и восстанавливает денежный запас добычей и продажей уже имеющегося сырья, без залога за будущую поставку.

Игровые правила исходной спецификации0.3 не изменены. Её SHA-256: `b86447e9311ab676538e1edbf7fd217c5a09896c3fc0d5edda7569ae088e9376`. Стартовая экономическая цепочка использует числовую фикстуру S1 с внешним покупателем вместо двусторонней сделки; полный рынок участников относится к P14–P16.

### Расчёты полного цикла

Начальные деньги участника1000.00; внешний бюджет столицы250.00, из которого100.00 остаются резервом закупки сырья. Получены10 брёвен, израсходованы в5 партиях, произведены/экспортированы5 досок. Зарплата20.00, энергия5.00, выручка150.00. Итог участника1125.00:

`1125 + 20 + 5 + 100 = 1000 + 250`.

Готового товара в инвентарях нет, единственная сделка на пять досок исполнена. Срок переносов от узла к предприятию и от предприятия к терминалу — по10 тиков; они не заменены мгновенной передачей.

Во втором сценарии начальные деньги0; проданы2 бревна по5.00. Итог10.00 у участника и90.00 неиспользованного городского бюджета; зарплата и энергия0. Hash: `b8491909a509b6eb0f0fe7f927151a79a3844c1d30e0c3c91d88d9d3e2bf80ab`.

## Ограничения среды и исправления

Первоначальный многопроцессный restore solution завершался без полезного вывода. С `--disable-parallel -m:1` он успешно завершён; проверки сборки используют один MSBuild-процесс и отключённые build servers. Это настройка выполнения в облаке, а не изменение игровых правил.

Первоначальный вызов dotnet test через VSTest был отклонён актуальным Microsoft.Testing.Platform на SDK10. После корректного включения MTP в global.json `dotnet test` остановился с `SocketException(13): Permission denied` при создании локального named pipe, exit134. Этот способ запуска **не прошёл**. По официально поддержанному пути запущена та же тестовая сборка через встроенный xUnit in-process runner; 34 теста действительно выполнены и прошли. Не использовались пустые заглушки или замена тестов печатью успеха.

Обнаруженные компилятором правила xUnit analyzer исправлены без отключения analyzers. SDK архив был повторно распакован без восстановления чужих uid/gid после ошибки ownership файловой системы.

Godot скачан отдельно от исходников и подтвердил версию, но здесь не создавался Godot-проект. Не проверены Windows export, Android SDK/workloads/templates, APK, устройство, pause/resume на телефоне, реклама или реальные локальные модели. Не измерены RAM/VRAM; manifest не подставляет выдуманные значения.

## Команды воспроизведения

Из корня Delsk, с установленным SDK10.0.401:

```bash
dotnet restore Delsk.sln --locked-mode --disable-parallel -m:1
dotnet build Delsk.sln -c Release --no-restore --disable-build-servers -m:1
dotnet tests/Simulation.Tests/bin/Release/net10.0/Simulation.Tests.dll -noColor -parallelMode none -result-trx artifacts/tests.trx
dotnet run --project src/Research.Runner -c Release --no-build -- --scenario scenarios/economic-cycle.json --output artifacts/cycle
dotnet run --project src/Research.Runner -c Release --no-build -- --scenario scenarios/zero-cash-recovery.json --script recovery --output artifacts/recovery
python scripts/verify_results.py artifacts/cycle artifacts/recovery
```

`--mode paced` существует в CLI, но длительный live paced прогон не выполнялся; scheduler проверен без реального ожидания в unit test. `final-state.json` — инспекционная выгрузка, а не обещание возможности загрузки. Текущий replay начинает с начального JSON-сценария и записанных команд. Полное сохранение/продолжение из середины пути — P12.
