## Результат

Карта сначала показывает полотно всего города. Есть fit/zoom/pan, выбор клетки и
полного footprint, маршрут к настоящему входу, слои, легенда и фильтр всех11 участников.
Колесо, перетаскивание, стрелки/WASD, Home, касание и pinch работают через GUI.
Фильтры раскрываются отдельно: Все / #1…#11, полное имя выбранного участника,
общая с миром цветовая легенда. Выбор не теряется при обновлении статуса, спроса,
брони или владельца. Пустая клетка не становится пунктом сторонней доставки.

Показаны ресурсы, промышленность, собственность/бронь/аренда, дороги и вклады
каждой ступени, публичные услуги, собственные и двусторонние ожидаемые поставки,
транспорт и участники. Карточка дороги сохраняет городскую основу и всех строителей,
показывает права100% города либо90% исполнителя/10% города. Частные запасы, счета,
цены закрытых сделок, escrow и quote tokens в DTO карты не копируются.

Карта, хозяйство, предприятие/цехи, техника, каталог услуг, заказы, оплаченные
покупки, задания и личный счёт связаны переходами в существующие карточки. Для
действий используются прежние commands/AccessFor и причины отказа; присутствие
на месте требуется по прежним правилам. Предварительный путь использует тот же
Core pathfinder, что MoveTo, и не создаёт traffic entries, время, деньги или PRNG.
Команда движения повторно валидируется по фактическому состоянию.

Счета, заявки, готовые работы и overflow имеют разные подписи, цвета и действия.
Уведомление самостоятельного дорожного улучшения строится по реальному вкладу,
как и уведомление выполненного городского заказа; одна ступень не уведомляется
дважды. Открытие ведёт к правильной клетке и карточке вкладов. Просмотр счёта
не платит; просмотр overflow не продлевает срок и не спасает груз. Просмотр
заявки не означает её принятия. ViewInvoice/ViewDeliveryService остаются обычными
командами; подготовка просмотра не мешает сразу подготовить принятие на паузе.
Уведомление само не останавливает время.

Пять коротких страниц объясняют путь: заработок → предприятие → цехи/задания →
транспорт/доставка → счета/переполнение. Это справка с переходами, без выдачи
ресурсов или наград. Обновления сохраняют страницы, выбор, scroll и ввод суммы/
количества; у услуги прогресс обновляется отдельно от структурных controls.
История заказов и хозяйство —20 на страницу; витрина событий ограничена100,
локальная память прочтения —512 отметками.

Узкие окна используют flow/scroll и адаптивные меню, каталог, оформление и нижнюю
панель времени. Safe-area margins рассчитываются по реальному окну/viewport.
Tab/Enter, Esc, закрытие помощи и focus pause согласованы; карта и текстовые поля
не пропускают WASD персонажу. Входы, уровни и собственные состояния зданий читаемы,
камера плавно меняет масштаб. Обе семьи скинов и10 человеческих моделей сохранены
для11 участников; косметика не меняет авторитетную геометрию и характеристики.

## Состояние и совместимость

Новых денежных правил и версии World нет: World28, session3 прежние. Все82
закреплённых финансовых/балансовых входа G1 совпадают по SHA256. Вклады дороги,
груз, деньги, персонал и права принадлежат прежнему Core; UI не ведёт второй учёт.
Настройки карты/прочтения/страница памятки — отдельный local config, не новые поля
авторитетного сохранения. При новой партии UI-память сбрасывается, при продолжении
восстанавливается.

Обнаружен старый край F2: отмена во время личной навигации меняет следующую цель
заказа раньше завершения уже начатого пути. Checkpoint validation теперь допускает
подлинную команду того же заказа с его согласованным исходным endpoint. Физика,
товар и расчёт не заменены. Расширена проверка точного продолжения и физического
возврата/refund. Ещё исправлен orphan скрытой service-кнопки в старых профилях
без Services: strict native logs больше не содержат RID/font/texture exit leaks.

## Воспроизведение и артефакты

С подготовленным .NET10.0.401 и Godot4.7.2 .NET:

```text
python scripts/run_check.py --name g2-unit --timeout 780 -- python scripts/check_headless.py --phase tests --suite ux --output artifacts/g2-unit
python scripts/run_check.py --name g2-developer --timeout 780 -- python scripts/check_developer.py --suite ux --output artifacts/g2-developer
python scripts/run_check.py --name g2-native --timeout 600 -- python scripts/check_city_experience_ui.py --godot PATH_TO_GODOT --output artifacts/g2-native --fixtures artifacts/g2-unit/g2-fixtures
```

Нужен доступный GUI display; на Linux можно передать `--display`. Output должен
быть новым или явно принадлежать runner (`--reuse-stage` + новый `--attempt`).
CI workflows сохраняют прежние gates. Скриншоты и JSON всех6 сцен доступны в
`windows-city-ux-ui` artifact указанного Windows run, `city-ux-ui/cases-a1/`:
`map-*.png`, `setup-*.png`, `invoice-*`, `service-*`, `overflow-*`, `work-*`,
`road-work-*`, `service-runs-*` и `native-check.json`. Инструкция игроку:
[CITY_EXPERIENCE_G2.md](CITY_EXPERIENCE_G2.md).

## Среда и ограничения

Настоящий телефон/планшет не использовался. Локально: Linux/X11, .NET10.0.401,
Godot4.7.2, software Mesa и Dummy audio. Windows — hosted Windows2025 VM с обычным
окном Godot, а не проверка на личном физическом ПК. Keyboard/mouse/touch проходят
настоящую GUI-диспетчеризацию синтетических событий; это не проверка физических
клавиатуры/сенсора. Safe areas проверены расчётом и UI-привязкой, не реальным
вырезом экрана. Аппаратные FPS/звук/термопрофиль и вся P80 остаются открытыми.

Полная естественная цепь доV, экономические сроки/ROI и превосходство Hard не
доказаны этой UI-итерацией. H1 запрошен пользователем как следующий отдельный
исследовательский этап. Числа баланса G2 не калибрует.
