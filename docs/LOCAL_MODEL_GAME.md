# Локальная модель в обычной партии (P56)

Автор: Шелестов Максим Евгеньевич.20.10.2026 (Europe/Samara).

В новой партии доступны Easy/Medium/Hard и переключатель алгоритм/гибрид. Сложность не меняется в процессе. Гибрид использует прежний HybridController/ModelRuntime/OllamaAdapter; один физический запрос, отдельный контекст каждого NPC, только предложенные допустимые планы/бюллетени. Параметры: localhost:11434, точное имя установленной модели, таймаут1–120с,1–10 запросов/NPC за120 ticks. Контекст4096/output512/temperature0/seed42; никаких автоматических установок или загрузок весов.

`LocalGameModel` в сохранённом HybridState — manifest композиции: model/endpoint/context/output/seed, runtime/queue/timeout, budget, `pause-at-decision-v1`, один явный retry. Это данные, не живые Task/HTTP. Конкретный адаптер подключается в Godot composition root; Hosting/Core не знают HTTP. TickScheduler получает дополнительный предикат барьера от хоста; остаток накопленного времени сбрасывается, UI не блокируется. Уже admitted очередь обслуживается `ProgressWaiting` без экономических тиков, ответы читаются на общем Freeze. На ошибке runtime есть retry (один на слот), отмена ожидания/переход в меню или алгоритм до конца партии; отменённый слот разрешается один раз с `UserFallback`. Невалидный/устаревший intent проходит прежний fallback/validator с записью причины; UI не показывает приватные prompt/response/договоры.

При load конфигурация восстанавливается из checkpoint. Pending/ready слоты становятся Interrupted и дают прежний `SessionRestored`, не новый HTTP; поздние callbacks другой эпохи не применяются. Replay — только записанные команды, без контроллеров/модели. Физический запрос, игнорирующий cancellation, не освобождает слот для второй inference; пользователь может продолжить алгоритмом.

## Открытая реальная приёмка

На текущей Linux-машине нет Ollama/весов; loopback11434 отказал в bounded проверке. Прошедшие программные тесты **не закрывают P56 целиком** и не подтверждают пригодность RTX5060/Android/Windows EXE.

На машине разработчика:

1. Установить Ollama отдельно, установить выбранную модель (исторический P23 использовал `qwen3.5:4b`), запустить `ollama serve`; `ollama list` должен показывать точное имя. Зафиксировать `ollama --version`, модель/tag/digest, GPU/VRAM/RAM/OS, наличие thinking=false.
2. Выполнить bounded restore/build клиента и тесты по HEADLESS_TESTING. Запустить Godot, выбрать карту/сложность/гибрид, имя модели, timeout до120с на холодный старт. Нажать «Проверить runtime и модель»: Available подтверждает только tags, не inference.
3. Начать новую партию. На первом слоте проверить, что tick не растёт до ответа, UI/меню доступны; ответ применён обычным validator. Сохранить checkpoint и исследовательские `ControllerTurns`/ModelTrace с latency/tokens/model/decisionId, prompt hash, resolution. Показать хотя бы один `ModelResolved/Accepted`; замерить первый и прогретый запрос отдельно. Не выдавать успешный tags за успешное решение.
4. Во время другого ожидания сохранить, загрузить: запрос этого слота не повторяется, появляется SessionRestored; replay исходного command tape при выключенной Ollama даёт тот же world hash. Сравнивать replay World, не недетерминированные wall-clock latency.
5. Остановить runtime перед новым запросом: мир ждёт ошибки, проверить bounded retry, затем «Продолжить алгоритмом», UserFallback и дальнейшее движение; снова load. Испорченный JSON/late/stale уже покрыты fixtures; для реального отрицательного gate также неверное имя модели/сервис выключен.
6. Приложить измеренные артефакты, manifest конфигурации из сохранения и хеши к PR отдельным commit. Только после этого закрывать P56. Режимы ожидания и runner tick-deadline нельзя смешивать в одной серии без маркировки.
