# Ресурсы и физическая автоматизация — пакет 3

Автор: Шелестов Максим Евгеньевич. 19.10.2026.

Обычная партия использует `config/economy.json`, профиль `presentation-economy-v4`. Нужна новая партия: World16 / Rules `physical-automation-1`; Session2 / Envelope2 сохранены. World15 не мигрируется и не перезаписывается. Старые сценарии остаются самостоятельными исследовательскими фикстурами со своими скоростями и правами.

## Ручной цикл

1. В каталоге выбрать одну из трёх карт. Первая и вторая получили явные версии `presentation-map-one-v2.json` и `presentation-map-two-v2.json`: прежние координаты сохранены, снизу добавлены две строки с общедоступной добычей. Старые файлы карт сохранены. Экономический профиль меняет баланс, география хранится в сценарии.
2. Подойти к лесу/зерну. На клетке видны запас, восстановление и права. Частную свободную клетку можно купить или исключительно арендовать; брони ресурса нет. Аренда длится1200 тиков. На границе срока незавершённая добыча отменяется, готовый личный товар остаётся. Новое списание требует новой команды.
3. Общедоступная добыча позволяет восстановиться без земли и денег. Она имеет меньший запас и более медленное восстановление; скорость ручной добычи единицы та же. Истощённый лес показывает пни.
4. Карточка собственного объекта → «Запасы и перенос»: одна единица, выбранное количество или всё доступное. Вместимость и чужие резервы ограничивают количество. При паузе команда ждёт включения времени. Заполнение кнопки отражает подтверждённую работу; товар появляется целыми завершёнными единицами. «Остановить передачу» и уход оставляют переданное и освобождают остаток резервов.

## Техника и доставка

Технику можно купить только на своей **купленной** совместимой ресурсной клетке. Личный и автоматический режимы используют тот же конечный запас. В автоматическом режиме карточка → «Маршруты»: щёлкнуть собственные остановки на мини-карте, выбрать повторение, сохранить/включить. Путь строит Core. Можно отдельно переехать к первой остановке. Изменение/выключение маршрута сохраняет уже начатый переход и груз.

При полном буфере машина ждёт вывоза. Когда вывоз освобождает место, добыча может продолжиться ещё до возвращения пустого грузовика. При истощении рассматривается следующая остановка; без допустимой работы маршрут ждёт. Нельзя уехать с потерей груза. Текущий вывоз блокирует переезд источника до завершения рейса, сохраняя действительные пути возврата. Для движения машины нужны команда и деньги; оплачиваются только реальные интервалы движения/добычи. Ожидание бесплатно.

У производства сначала купить существующую доставку. В его карточке → «Маршруты» выбрать собственный источник, собственный получатель и товар. Источник: буфер техники, вход/выход своего здания; получатель: вход своего склада/лавки/совместимого производства. Личные инвентари, чужие запасы и управляемый груз не являются источником этого маршрута. Это прежняя система логистики с одной очередью и одним активным грузом, без отдельного парка машин. Количество определяется свободным товаром и вместимостью.

Подвоз на вход базы управляется переключателем входящих поставок, остальные маршруты — исходящей отправки; производство независимо от обоих. Приоритеты очереди прежние: ближайший срок обязательства, риск простоя от нехватки входа, освобождение выхода; затем воспроизводимое обслуживание равных. Редактирование меняет будущую работу, активный рейс завершается. Причины ожидания показаны в карточке. Пределы пилота:32 остановки добычи,64 задания очереди.

Погрузка/разгрузка используют накопленную работу. В обычном профиле личная скорость4 объёма/тик, командная4 × уровень доставки × **текущая** численность. При нулевой команде обработка ждёт. Уже начатое движение грузовика сохраняет зафиксированную скорость. Бюджет резервируется консервативно с учётом пути и обработки, платится фактической численности, остаток возвращается; новая ставка ждёт фактического завершения рейса. Опоздавший груз физически возвращается в источник, без исчезновения/повторной оплаты.

Стены задаются клетками `buildingTypes[].walls`, отдельно от собственности. Якорь здания — проход/ворота; открытая лесопилка проходима. Пеший ход, NPC, грузовик и мини-карта используют эти данные. Стройка, которая перекрыла бы выданное получение товара или зафиксированный путь, отклоняется до оплаты; сложной перестройки маршрута в движении нет.

## Баланс пилота

| Параметр | Значение / источник |
| --- | --- |
| Личная/командная обработка | `world.rules.handling`:4 /4 объёма за тик |
| Частный ресурс | `world.resources[].private`: запас200, восстановление10/120 тиков |
| Общедоступный ресурс | `world.resources[].public`: запас50, восстановление2/120 тиков |
| Покупка / аренда частной клетки |10000 /1000 minor;100 minor =1 денежная единица |
| Срок аренды |1200 тиков |

Это начальные параметры, не доказанный окончательный баланс. Публичные права/природный запас не раскрывают личные запасы, планы, грузы и секретную поддержку участников. Купленная ресурсная земля входит в капитал по фиксированной нормативной цене; аренда и природный запас не считаются созданным товаром.

## Проверки

Каждая команда ниже запускает собственные bounded checks с логами. Сначала обычный .NET SDK по `global.json`; Godot4.7.2 Mono нужен отдельно для клиента.

```bash
python scripts/check_headless.py --output artifacts/package3-headless
python scripts/check_developer.py --output artifacts/package3-developer
python scripts/check_physical_automation.py --output artifacts/package3-maps
dotnet restore src/Client.Godot/Delsk.Client.sln --locked-mode
dotnet build src/Client.Godot/Delsk.Client.sln -c Debug --no-restore
```

Godot `--headless --path src/Client.Godot res://PlatformProbe.tscn -- --smoke --report ABSOLUTE_REPORT_PATH` сравнивает runner-хеши экономического, политического и физического сценариев; `scripts/verify_platform_probe.py` проверяет отчёт и логи. Запускать через `scripts/run_check.py` с timeout120. Обновлять эталонные хеши только из проверенных runner-артефактов через `scripts/update_platform_fixture.py` с `--stopped-directory` и `--physical-directory`, после проверки причин изменения правил.

Аппаратная приёмка Windows EXE/Android, новая живая модель, длительная партия и FPS остаются отдельными проверками. Следующий пакет4 — P43–P47; текущая работа их не реализует.
