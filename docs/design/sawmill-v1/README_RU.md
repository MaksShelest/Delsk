# Delsk — планшет лесопилки, вариант 01

Автор проекта: Шелестов Максим Евгеньевич.

Первый визуальный вариант: светлая мастерская, лесные зелёные оттенки, охра, крупные пиктограммы. Это самостоятельный прототип интерфейса с демонстрационными данными. Экономика Delsk не изменена и не подключена.

## Посмотреть

`previews/01-sawmill.png` — основной экран, действительно отрисованный Godot.
`previews/02-delivery.png` — дополнительное окно грузовика.

Открыть `project.godot` в Godot 4 и запустить проект. Для визуальной части .NET не нужен; её можно использовать и в Godot .NET. Проверено на Godot 4.5.1, Compatibility, Linux. Windows, Android и иные версии движка этим заданием не проверялись.

## Перенести в Delsk

1. Скопировать папку `delsk_sawmill_ui` в корень существующего проекта, сохранив имя папки.
2. Добавить `res://delsk_sawmill_ui/SawmillTablet.tscn` как экземпляр сцены в слой интерфейса.
3. Подключить существующий C# presenter / адаптер команд к именованным узлам. В самой сцене нет скрипта и авторитетных расчётов.
4. Заменить примерные значения состоянием из разрешённой проекции игры. Доступность действий и причины отказа брать из Core; удалённый просмотр не даёт права менять зарплату, покупать транспорт или передавать товар.

Не копировать `project.godot` поверх настроек игры. `Demo.tscn` и `demo.gd` нужны только для просмотра: они показывают раскрывающиеся окна и изменения выбранных настроек, испускают `ui_action`, но не исполняют экономические команды и не списывают ресурсы.

Экран рассчитан на логическую область 1440×1024 и масштабируется в демопроекте с сохранением пропорций. Это первый планшет для обсуждения на большом экране. Отдельная компоновка для маленького телефона, реальные переводы RU/EN и обработка подтверждений Core остаются этапом интеграции.

## Где находятся действия

Пути ниже отсчитываются от узла `SawmillTablet/Panel`.

| Действие | Узел / элемент |
| --- | --- |
| Рецепт и прогресс | `Production`, `Production/Progress` |
| Остановить / запустить производство | `Production/PauseProduction` |
| Работники и места | `Workers/Headcount` |
| Ставка производства, шаг 0,05 | `Workers/WageMinus`, `Workers/WagePlus` |
| Входной и выходной запас | `Stock/WoodCount`, `Stock/PlankCount` |
| Ручная передача по одной единице | `Stock/Deposit`, `Stock/Withdraw` |
| Улучшить производство | `Upgrade/UpgradeProduction` |
| Остановить / возобновить подвоз | `Delivery/SupplyToggle` |
| Выбрать источник сырья | `Delivery/Source` |
| Отправлять готовую продукцию | `Delivery/SendToggle` |
| Выбрать получателя / договор | `Delivery/Destination` |
| Транспорт, численность, отдельная зарплата, улучшение | `Delivery/DeliverySettings` |
| Приобрести отсутствующий транспорт | `Delivery/NoTransport/BuyTransport` |
| Пауза при открытом планшете | `TimeToggle` |
| Справка / закрытие | `Help`, `Close` |

Дополнительные окна в `demo.gd` создаются обычными Control-узлами, а не HTML. Для интеграции их обработчики следует заменить существующим C# представлением; образцы показывают расположение информации и последовательность действий. Покупка и улучшение испускают намерение, а не демонстрируют несуществующую успешную оплату.

## Показанные состояния

По умолчанию: игрок рядом со своей лесопилкой, предприятие уровня 1 работает, транспорт приобретён. Оба направления доставки включены. Общая игровая пауза и остановка отдельного производства — разные состояния.

Для снимка состояния можно передать аргумент после `--`: `--view=delivery`, `--view=routes`, `--view=paused` или `--view=no_transport`. Вариант `no_transport` показывает покупку вместо управления рейсами. После закрытия планшета клавиша Esc возвращает его на экран.

Все суммы, количества, сроки, цены и договоры в примере — фиксированные данные для дизайна. В частности, ставки 0,20 и шаг 0,05 взяты из более позднего плана; остальные характеристики иллюстрируют исходный стенд. Они не заменяют актуальные конфигурации игры. Рецепт, характеристики улучшения, источники, права и доступные договоры должны поступать из игры.

Обязательные особенности для интеграции: независимые переключатели; завершение уже начатого рейса; отсутствие мгновенного найма при изменении ставки; улучшение только с местными материалами; автоматический остаток по конкретному договору; запрет двойной продажи / отправки зарезервированных товаров; корректные пояснения причин ожидания; отсутствие экономического исполнения на общей паузе.

## Проверено

- Импорт и запуск исходной сцены в Godot, фактический PNG-снимок через OpenGL/Mesa.
- Читаемость основного экрана и окна доставки при 1440×1024.
- Независимость трёх переключателей; шаг зарплаты 0,05 без изменения численности; открытие дополнительных окон; выбор договорного получателя; отдельная пауза времени.

Это проверки интерфейсного прототипа, не тестирование игровой симуляции.
