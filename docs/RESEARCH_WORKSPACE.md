# Исследовательское пространство Delsk

Автор: Шелестов Максим Евгеньевич. 23.10.2026.

Расширение P58 после PR51. Запуск остаётся прежним: ResearchLab.cmd на
Windows или sh ResearchLab.sh на Linux/macOS из полной папки исходников.
Нужны Python3.10+ и SDK10.0.401; пакеты pip/npm для работы не нужны.
Лаборатория работает отдельно от игры. Все правила и вычисления выполняет
прежний C# runner. Windows double-click/macOS hardware этой Linux-проверкой
не подтверждены.

## Навигация

- **Все исследования**: поиск, состояние, число завершённых прогонов и
  размер файлов. Флажки выбирают опыты для сравнения/удаления.
- **Новое исследование**: основные условия, участники, экономика и полный
  JSON. Четыре готовых исследования сохранены. Можно добавить scalar-факторы.
- **Профили экономики**: независимые копии настроек. Использование профиля
  подставляет его в новый опыт, не переписывает предыдущий.
- **Модели и подключения**: профили Ollama, список установленного через
  /api/tags. Каталог моделей не доказывает успешный inference.

В карточке опыта доступны вкладки «Прогоны», «Мир по шагам»,
«События и решения», «Анализ», «Файлы». Выбор прогона и попытки расположен
над вкладками и действует на все представления. Таблица прогонов выводится
по50строк. Прежние попытки остаются на диске и доступны переключателем.

Переименование меняет отображаемое название, не ID/пути. Архив скрывает опыт
и исключает его queued-прогоны из запуска. Дублирование копирует настройки,
не готовые результаты. Удаление/групповое удаление требует явного подтверждения
в браузере и удаляет файлы выбранных опытов с диска. Активный опыт нельзя
удалить/архивировать; сначала завершить или остановить его.

## Прогресс, пауза, остановка

Показаны тик/цель/процент, elapsed, скорость, число модельных запросов,
lastAdvancedAt и heartbeatAt. Разные состояния: запуск, running, paused,
waiting-model, voting, exporting, completed, cancelled, failed.
Свежий heartbeat при неизменном тике отличает работу хоста от продвижения мира.
Это диагностические факты, а не автоматическое доказательство причины зависания.
Перед первым progress.json отображается подготовка исходного мира; stderr
попытки доступен во вкладке файлов.

**Пауза очереди** действует между ограниченными прогонами. **Пауза прогона**
останавливает текущий runner на границе атомарных шагов. **Продолжить**
снимает эту паузу. **Остановить** отменяет текущую попытку и ставит очередь
на паузу; частичные кадры/журналы/экспорты сохраняются, status=cancelled,
exit2, результат исключается из статистики. Экспорт уже начавшегося
завершённого шага не обрезается.

Жёсткий timeout по-прежнему ограничивает **всё** время процесса, включая
ручную паузу. Для длительного чтения остановите опыт или заранее задайте
больший лимит (до900секунд). Если он исчерпан, попытка failed/timeout,
файлы остаются. Shutdown запрещает новые запуски и ждёт активный bounded
прогон. Crash превращает running в interrupted; повтор только явный и
в новой папке попытки. Пауза активного прогона доступна для записываемых
исследований; profile=true/recordWorld=false — CLI-режим без этого observer.

## Начальные условия и участники

Состав: один пассивный human-слот и1–15NPC. В headless человек не ведёт
хозяйство, но голосует за себя; это явно записано в плане. Число NPC не
меняет число доступных клеток выбранной карты: дефицит мест — условие опыта.

По участнику задаются стартовая клетка, деньги, вместимость, предпочтение,
сложность, модель либо алгоритм. Стартовые клетки должны различаться,
быть внутри карты и проходить Core validation. Новые предложенные клетки
располагаются ближе к терминалу; это предложение формы, не изменение правил.
Настраиваемые деньги — целые сотые монеты; ввод37.25 означает3725.
Вместимость — характеристика пустого личного инвентаря; стартовый товар
этим интерфейсом не выдаётся.

После редактирования состава персональные начальные значения имеют
приоритет над общим StartingCash/PersonalInventoryCapacity профиля.
Остальные числовые настройки мира/экономики задаются формами со строкой
поиска. Каталоги и массивы рецептов остаются в JSON. Там же доступны
остальные прежние параметры полного плана. Формы не рассчитывают экономику:
все arms проходят настоящий валидатор runner до публикации серии в очереди.
Более16участников и UI seed за пределами безопасного JS integer не допускаются;
прежний CLI сохраняет поддержку uint64 seed.

Новые optional поля плана: economyData (полный профиль-копия), participants,
modelData (прежний model config плюс bindings), recordWorld.
Прежние scenario/economy/controllers/modelConfig paths и CLI продолжают
работать. JSON не допускает дублирующихся ключей и неизвестных полей.
Массивы экономики должны отвечать прежней схеме Core.

## Модели и тайминг

Каждый NPC может получить свой профиль Ollama либо алгоритм. Пример
bindings в modelData/model-config:

```json
{
  "policy": {
    "minimumIntervalTicks": 30,
    "applyDelayTicks": 2,
    "decisionTtlTicks": 2,
    "budgetPeriodTicks": 120,
    "maximumRequestsPerPeriod": 2
  },
  "runtime": { "queueCapacity": 3, "timeoutMilliseconds": 30000 },
  "bindings": {
    "2": { "endpoint": "http://127.0.0.1:11434/", "model": "qwen3.5:4b" },
    "3": null,
    "4": { "endpoint": "http://127.0.0.1:11434/", "model": "qwen3.5:9b" }
  }
}
```

Неуказанный/null actor в явном bindings использует алгоритм. Без bindings
сохраняется прежний общий ollama-профиль. Один общий ModelRuntime обслуживает
разные адаптеры с прежней очередью, capacity, timeout/fallback; параллельный
inference скрыто не включён. Ожидание обслуживает уже принятую очередь и
не вызывает Core.Step. Новые опыты фиксируют ResearchWaitAtDecision-v1.
Прежний CLI без --model-wait сохраняет свой deadline timing. Сравнивать
с ними новую timing-группу как одну и ту же нельзя.

Профиль модели описывает тег, адрес, контекст и output bound; тег не является
измеренным digest весов. Наличие профиля не подтверждает доступность модели.
Недоступный runtime даёт прежний ограниченный fallback, который виден в
журнале. Для настоящего исследования зафиксировать фактические веса/runtime
и выполнить живой inference по LOCAL_MODEL_GAME.md.

ModelServices при load принимает все NPC IDs, включая алгоритмические
bindings. Pending checkpoint-слоты прерываются прежней политикой без
повторного запроса. Replay читает записанные команды и не создаёт inference.
Cloud API/ключи/автоматическая установка моделей остаются будущей работой;
адаптеры отделены от Core, поэтому расширение не требует менять экономику.

## История и файлы

В каждой записываемой попытке:

| Файл | Содержание |
| --- | --- |
| progress.json | Последний живой статус, heartbeat и диагностика |
| control.json | Cooperative running/paused/cancelled |
| world-scenario.json | Разрешённая география и стартовая конфигурация |
| world-frames.jsonl | Кадр каждого завершённого тика, хеш, реальное состояние объектов |
| world-index.jsonl | Tick, UTF-8 byte offset и длина кадра |
| live-events.jsonl | Исследовательские события |
| live-decisions.jsonl | Реальные решения контроллеров с наблюдением/feedback |
| model-transcripts.jsonl | Фактические запросы и ответы моделей, Requested/Completed |

Старые scenario/summary/manifest/final-state/agents/labor/commands/events/
ledger и остальные CSV/JSON/JSONL остаются. Новый observer пишет на диск,
не создаёт второй симулятор. Кадр замороженных выборов публикуется после
фактического подсчёта. Полная непрерывная последовательность0..finalTick
и конечный stateHash проверяются до включения попытки в clean statistics.
Конечный replay сначала подаёт бюллетени на границе, затем завершает запись.

Мир можно просматривать по номеру шага, ползунком и воспроизведением
сохранённых кадров; это просмотр записи, не новая симуляция.
Журналы фильтруются по категории/actor/тексту/проблемным записям,
выводятся страницами. «Только проблемы» — текстовый фильтр по словам
ошибки/отказа/fallback, не самостоятельная классификация тяжести.
Raw JSON каждой записи раскрывается.

Файлы просматриваются в браузере без скачивания, блоками до64KiB с
продолжением по byte cursor. Большой JSON может показываться текстовыми
фрагментами; исходник можно скачать. Выбор попытки исключает файлы других
попыток из списка. ZIP включает всю серию и прежние попытки; недоступен
во время running. Для CSV графиков прореживание отдельно по каждому actor
сохраняет все линии и конечные точки; исходные строки не удаляются.

Исследовательские записи содержат собственные и секретные сведения всех
сторон. Доступ только локальному исследователю с token/Host/Origin guards;
NPC/публичный игровой UI эти файлы не получают. Просмотр/удаление ограничены
известными папками опыта; выход за них и внешние symlink отклоняются.

## Сравнение и воспроизводимость

Успех — code0, полноценный export и полная запись, если она запрошена.
Failed/interrupted/cancelled/Developer/intervened результаты не входят в
чистые сводки. Нулевой выпуск допустим и не превращается в ошибку баланса.
Нет latency — null, нет данных — не вымышленный ноль.

План и валидированные входы копируются; фиксируются их SHA256 и хеши DLL
runner. Изменённые inputs или подменённый бинарник не выполняются внутри
прежней серии. Начните новую серию после обновления программы.

Парное сравнение требует одинаковых географии, стартов, горизонта,
бинарников и недекларированных параметров. Различия разрешены только по
названным scalar-факторам и явно зафиксированным режиму/конфигурации модели.
Контрасты записываются в pairedRightMinusLeft.declaredContrasts.
Разные timing-группы не смешиваются. Seed/repeat связывают пары; повтор
одного seed не увеличивает число независимых seed. Совпадение геометрии
не доказывает экономического баланса.

Ограничения старой полной истории/RAM/save/load остаются. Кадры дополнительно
занимают диск и время; предел10000тиков — ограничение ввода, не обещание
быстрой/мобильной работы на этом горизонте.
