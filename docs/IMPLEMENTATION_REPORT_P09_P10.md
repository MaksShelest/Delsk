## Сделано

Реализованы две связанные задачи: числовой рынок труда и постепенные переходы. Общие Core/Hosting используются runner и Godot; объектов жителей, индивидуальных кошельков и второй экономики нет.

- Population/Unemployed/EmploymentGroup, настраиваемый числовой прирост и инвариант сохранения населения каждый тик.
- Готовность вакансии отдельно от оплаченной работы; нулевой штат и группа ниже minCrew могут нанимать. WIP сохраняет права на вход/выход, двойного списания при возобновлении нет.
- Точный wage³ water filling с ограничениями мест, широкими целыми и воспроизводимым округлением. Общий кошелёк не обещается нескольким группам одновременно.
- SetWage с проверкой владельца/диапазона/переполнения. Оплата t+1, привлекательность t+20 по умолчанию; новая команда заменяет pending значение.
- Одновременные кадровые delta, накопление дробной квоты малых групп, предел накопления; зарплата0 при простое, конечный отток, постепенный повторный найм. Upgrade сохраняет фактический штат/ставку, увеличивает только места.
- Проекции собственного/публичного кадрового состояния, события фазы5, labor.csv и численности в metrics.csv; полный hash/replay учитывает остатки, pending wages, прирост и labor PRNG.
- `--script labor`, сценарий `labor-dynamics.json`, проверки в CI, обновлённые контрольные хеши прежнего Godot-стенда, инструкция [LOCAL_SETUP.md](LOCAL_SETUP.md).

## Границы и оставшиеся проверки

В исторических regression JSON явно указан laborStep10000/growth0 для сохранения их короткого фиксированного стенда. Обычные настройки LaborSettings10/20/1⁄10/+1за120 и новые integration-тесты действительно меняют N; не выдавать прежние фикстуры за динамический режим.

Windows/Godot CI для этого PR проверяется отдельно; актуальный результат и ссылки публикуются в PR. Новый Android APK и Windows EXE в этой итерации не экспортировались; предыдущие P06 бинарные файлы содержат старую версию правил. На реальном телефоне/в готовом Windows EXE эту версию не запускали. Rider здесь не запускался: подготовлены исходники и воспроизводимые локальные команды по официальной документации.

Нет интерактивной карточки зарплат в Godot (P26), добывающей техники/автологистики (P11/P17), load checkpoint (P12), автономных NPC (P13/P21), полного рынка/политики/модельного адаптера (последующие задачи). Их месячный объём сохранён. `final-state.json` — inspection export, replay начинается с initial scenario и записанных команд. Утверждения о загрузке продолжающейся игры не сделаны.
