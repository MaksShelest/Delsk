# Debug, режим бога и стандартный экспорт Godot

Автор: Шелестов Максим Евгеньевич.21.10.2026 (Europe/Samara).

## Обычный способ — галочка в Godot

Откройте **основной** проект `src/Client.Godot/project.godot` в Godot4.7.2 **.NET/Mono**. Нужны .NET SDK10.0.401 и соответствующие Windows .NET export templates (Редактор → Управление шаблонами экспорта).

1. Проект → Экспорт, выбрать Windows-профиль (в репозитории он называется **Windows Probe**).
2. Нажать «Экспортировать проект…», выбрать файл .exe.
3. **«Экспорт с отладкой» / Export With Debug включена:** Debug-меню и режим бога включаются автоматически.
4. **Галочка выключена:** Release, без Debug-меню и Developer API.

Python, ручные MSBuild-флаги и копия исходников для этого способа **не нужны**. Храните .exe вместе с .pck и соседней data-папкой, созданной Godot. Если релиз экспортируется поверх debug в ту же папку, включённый проектом небольшой editor-addon удаляет только остаточные Simulation.Developer.dll/.pdb из собственного managed bundle, подтвердив релизный deps manifest. Соседние экспорты/пользовательские файлы не трогаются; при неудавшемся release с прежним debug manifest ничего не удаляется. Addon не входит в PCK.

В готовой debug-игре: **Меню → Debug-режим → «Режим бога»** (верхняя строка у2Dкарты). Либо Меню → «Разработчик · режим бога и журнал». Выбрать «Вы», затем «Деньги, монет» или хранилище/ресурс/количество и соответствующее «Применить».

Ввод — итоговое общее количество, не добавка. Для больших запасов выбрать подходящий склад: резервы и вместимость сохраняются. Деньги вводятся в монетах (123.45 →12345minor).

| Операция | Конфигурация | Debug / режим бога |
|---|---|---|
| Экспорт с галочкой | ExportDebug | Оба включены |
| Экспорт без галочки | ExportRelease | Оба отсутствуют |
| Обычный запуск из редактора | Debug | Технический Debug; подсказка про debug-экспорт |
| Дополнительная изолированная Developer-копия | Debug / ExportDebug | Оба включены |

Основной экспорт сохраняет Godot app name Delsk; debug/release saves разделены суффиксом, см. ниже. Не открывайте старую `artifacts/developer-client/source/...` копию для получения обычного релиза: она специально закреплена как Developer. Используйте исходный основной проект.

## Дополнительный способ для автоматизации

Скрипт остаётся доступным, но для стандартной галочки не требуется:

```powershell
python scripts/build_developer_client.py --output artifacts/developer-client --export-windows --godot "C:\Godot\Godot_v4.7.2-stable_mono_win64_console.exe"
```

Он создаёт `artifacts/developer-client/windows/DelskDeveloper.exe` и соседние файлы. Для запуска из редактора отдельной Developer-копии достаточно `python scripts/build_developer_client.py --output artifacts/developer-client`, затем открыть её project.godot. Исходники редактировать в репозитории; stage может быть пересоздан только packager в каталоге с маркером.

Ручной Developer Debug исходного проекта по-прежнему защищён require-stage guard. **ExportDebug основного проекта больше не требует stage:** root props выбирают Developer по конфигурации и одинаково для всех references. Release с явно принудительным DelskDeveloper=true остаётся ошибкой; обычная выключенная галочка не задаёт этот флаг и собирается штатно.

Фактическая проверка стандартного экспорта: [IMPLEMENTATION_REPORT_STANDARD_DEBUG_EXPORT.md](IMPLEMENTATION_REPORT_STANDARD_DEBUG_EXPORT.md). Предыдущий альтернативный способ/исторические gates: [IMPLEMENTATION_REPORT_DEBUG_BUILDS.md](IMPLEMENTATION_REPORT_DEBUG_BUILDS.md).

Сохранения Developer имеют суффикс `-developer` и метку пакета. Релиз и обычный запуск из редактора их отклоняют. Developer может открыть нормальный checkpoint как отладочную копию; оригинал не перезаписывается. Любой Developer-прогон имеет `cleanComparisonEligible=false`, даже до первого вмешательства. Чистые paired series его не принимают.

Меню → Debug → **«Режим бога»** (либо Меню → «Разработчик»). Вкладка «Режим бога»: выберите участника (по умолчанию человек), задайте целевое количество денег **в монетах** или целевой **общий** запас выбранного ресурса в выбранном хранилище и нажмите «Применить» рядом с соответствующим полем. Например, `123.45` монеты превращаются в `12345` minor; это конечный баланс, не прибавка. Нулевой запас удаляет только свободный товар. Текущий баланс, резервы, количество и занятый объём показаны рядом. Рюкзак выбран по умолчанию; остальные хранилища различаются ID и координатами. Отдельно доступен коэффициент привлекательности зарплаты1–5. Core применяет существующие транзакции: нельзя изъять зарезервированный товар/деньги, занять обещанную вместимость или редактировать управляемый cargo. Цель ограничена10¹²; каждое применение содержит tick/sequence/actor/old/new и позицию в ленте входов. На голосовании, внутри Step и между travel quanta вмешательства запрещены. Вместимость, unitVolume и произвольные каталоги не редактируются. Базовый config/hash не заменяется; отдельный override восстанавливается и воспроизводится.

Журнал хранит последние256 записей, не чаще настоящих decision/feedback barriers; до16 оценённых feasible candidates, выбранная цель/причина/шаг, команды/результаты, разрешённое наблюдение. Текст наблюдения/запроса ограничен16K символов, ответа4K; длительность и fallback отдельно. Данные только из существующих ControllerTurn/ModelTrace, без конфигурационных секретов подключения. Внутренний журнал исследователя содержит разрешённые двусторонние условия; обычный игровой экран их третьей стороне не показывает. Полная существующая исследовательская session history остаётся в checkpoint и сохраняет ограничения размера/памяти P27; новый ограниченный экран не решает эту отдельную проблему.

## Окно разработчика и ресурсы HUD

Вход с Debug и прежний вход из меню открывают одно окно: «Режим бога», «Перемотка», «Решения NPC». Мир остаётся на паузе, кроме явно запущенной перемотки. Escape или «Закрыть» закрывает только это окно, сохраняет исходный экран и отменяет перемотку. Фон перехватывает мышь; клавиатура окна не выбирает действия в Debug под ним. Если вмешательство отклонено из-за незавершённого хода, закройте окно и завершите ход кнопкой шага в Debug; при остановленных выборах сначала проголосуйте.

В обычном игровом HUD показываются только положительные **физические** запасы рюкзака. Зарезервированный, но ещё находящийся в рюкзаке товар остаётся видимым. Нулевые товары не занимают места. Колонки содержат до двух ресурсов: древесина/доски, зерно/хлеб, молоко/сыр, свёкла/сахар, выпечка отдельно. Новые неизвестные товары не теряются: добавляются по два в следующих колонках. Названия доступны при наведении; язык переключается вместе с UI. Высота прежней верхней панели сохраняется.

Проверка интерфейса в изолированном клиенте (требует .NET и Godot .NET):

```text
python scripts/check_hud_god_ui.py --godot PATH_TO_GODOT --output artifacts/hud-god-ui
```

Она проверяет настоящие Godot controls и Developer-транзакции в headless-режиме: вход с Debug, деньги в монетах, запас и отказ при переполнении, смену участника, паузу/закрытие, фильтр нулей, двухрядные группы и локализацию. Класс теста копируется только во временную сборку. Windows CI запускает эту проверку после обычного клиента и проверки отсутствия Developer API. Это не аппаратная проверка FPS или визуальная приёмка глазами.

## Перемотка и replay

На вкладке «Перемотка» задайте абсолютный будущий тик либо N тиков и нажмите «Применить». Выполняются настоящие Step, максимум8 за кадр; бюджет8ms проверяется **между** атомарными шагами, один тяжёлый Step не прерывается. Есть отмена. Перемотка останавливается на голосовании, ожидании модели и победе. Меню допускает явно запущенную Developer-перемотку; потеря фокуса/сворачивание/справка её приостанавливают. Это не откат времени.

До запуска можно явно выбрать временный self-ballot человеческого слота, с соблюдением подписанной поддержки; выбор маркируется в аудите. Он действует только для этого запуска перемотки. После load перемотка автоматически не возобновляется; сделанные вмешательства и принятые бюллетени сохраняются. Для следующего запуска политика задаётся заново. Без этой политики требуется настоящий человеческий бюллетень.

Backend-проверка и Developer runner:

```text
python scripts/check_developer.py --output artifacts/developer-gate
dotnet src/Research.Runner/bin/developer/Debug/net10.0/Research.Runner.dll --scenario RUN/scenario.json --replay RUN/commands.jsonl --research-modifications RUN/research-modifications.json --ticks FINAL --output artifacts/developer-replay
```

`--research-modifications` существует только в Developer runner; вход до1MiB/1024 записей. Порядок/старые значения/границы проверяются. Обычный replay не вызывает модель; Developer replay дополнительно повторяет аудит в той же позиции входов. Применённые решения, а не новые ответы модели, определяют результат.

## Выборы обычной игры

Профиль `presentation-economy-v3` явно задаёт600 тиков и `pauseForBallots=true`. В фазе8 фиксируются текущие группы после кадрового шага; тик завершается один раз. Затем Core принимает только SetVoteChoice текущих выборов как отдельный control input с issued/notBefore/expires равными замороженному tick. Ни один дополнительный Step не нужен. Один принятый бюллетень на участника, повторный ID идемпотентен, другие повторные попытки отклоняются. Signed support задаёт обязательного кандидата. После всех бюллетеней однократно публикуется tally/результат и выполняется договор, включая отсутствие победителя.

Клиент открывает политический планшет, сохраняет независимые menu/help/focus/tablet pauses и показывает публичный результат. При ожидании не меняются N, зарплаты, WIP, груз, дедлайны и PRNG. NPC голосует через тот же валидатор; Hybrid использует общий ограниченный runtime и строгий parser. Он может получить ответ/timeout/fallback без изменения tick. Незавершённый slot после load получает fallback нового epoch без повторного запроса; поздний ответ его не заменяет.

Исторические regression fixtures сохраняют автоматический P19 tally (`pauseForBallots=false`, default legacy settings); это не режим обычной новой партии. В headless новой партии требуется явная политика человека:

```text
dotnet src/Research.Runner/bin/Release/net10.0/Research.Runner.dll --script baseline --economy config/economy.json --human-ballot self --ticks 1200 --output artifacts/ordinary-1200
```

Она сохраняется как SelfBallotController, без экономических действий. Текущие версии: World15/Rules stopped-elections-1, Session2/Envelope2. World14 не мигрируется; прежние файлы/пути остаются. Проверки и ограничения — [отчёт пакета2](IMPLEMENTATION_REPORT_PACKAGE2.md).
