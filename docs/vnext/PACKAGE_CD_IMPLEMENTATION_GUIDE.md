## 4. Уточнения реализации C

Это технические уточнения к принятой спецификации, не новый баланс.

**Ground.** Один обычный объём70 на собственной пустой покупаемой клетке, включая разные товары. Не на общественной земле/коридоре/чужом участке. Физический inventory/права/координаты, ручные Transfer с длительностью; нельзя назначить route/service/market endpoint или создать бесплатный склад с купленной бронью. После начала стройки не удалять оставшиеся товары и не открывать к ним чужой доступ.

**Overflow.** Отдельный lot с ID/owner/item/quantity/source/location/createdTick/expiresTick, без отрицательной ёмкости и смешения с normal holds. `normalVolume + normal holds <= capacity` остаётся строгим. Для приёмки сначала normal в пределах доступного места, остаток только по разрешённому системному основанию (согласованная arriving delivery/демонтаж). Обычный manual/production/новая route не может запросить emergency=true. F ещё не реализован: C1 готовит узкий механизм и проверяет его реальным существующим arrival path или явно именованной integration fixture, а не фиктивной услугой.

1200 активных тиков; предупреждения при создании и остатке600/120, без повторов после load. Принятое техническое правило границы: `expiresTick = createdTick + 1200`; допустимый ручной вывоз/normalization выполняется в обычной фазе до phase7 expiry того же тика. В phase7 исчезает только ещё не спасённый остаток. Следовательно тики expiresTick−1/expiresTick/expiresTick+1 покрыты отдельными проверками. Не менять экономический порядок фаз ради UI.

Normalizing — только свободное место после чужих/своих действующих holds, целые единицы и права владельца. При конкуренции lot: стабильный порядок expiresTick/createdTick/ID. Manual rescue разрешён; обычный reserve/market/recipe/политическая поставка overflow не обещает. Перенос не должен бесконечно продлевать срок того же рискованного груза; настоящий переход в normal снимает риск. Pause/help/model barrier/offline не продвигают таймер. Излишек после срока — отдельный flow sink, а не отрицательный Produced.

**Учёт.** Возврат стройматериалов — отдельный recovery flow/capital-to-stock transfer с сохранением старого gross ConstructionInput; нельзя одновременно уменьшить ConstructionInput и добавить recovery второй раз. Реальный stock/WIP/overflow/вложенный капитал учитываются ровно один раз в капитале/товарном равенстве. Overflow expiry — отдельная потеря; различать её и материалы, оставшиеся вложенными/утраченные при сносе. Перевозчик не владеет второй копией принятого товара.

**Вложения и проекты.** C1 при новых warehouse проектах уже пишет реальные per-building/per-cell вложения, чтобы C2 не восстанавливал историю из текущего прайса. C2 расширяет это на Build/Upgrade/прочие реальные вложения, D1/D2/D3 сохраняют тот же механизм. Склад:100/250/600монет, материалы10plank /20plank+4steel /6beam+10concrete,60/120/180тиков; земля отдельно. Наличие рецепта beam/concrete в каталоге до D3 не обещает доступную рыночную поставку: L2/L3 проверяются prepared fixtures и честно объясняются как зависящие от D3.

**Снос.** `30*N + 15*Σmax(0,Lcell−1)` монет, без возврата денег;60% суммы фактически вложенного каждого ItemId с одним floor после суммирования, не floor каждой записи. Физический stock100%, съёмные equipment100% ровно один раз. Численность сохраняется в общей population, переводится в unemployed; XP/земля остаются. «Подготовить» запрещает новые партии/рейсы, но даёт начатым завершиться/вернуться, сохраняет доступ к нужным пополнениям/вывозу; обычный Stop, навечно заморозивший WIP, не заменяет эту операцию. Начатый строительный проект можно явно прекратить на безопасной границе и затем снести его незавершённый объект/часть через C2: неиспользованные holds освобождаются, фактические вложения возвращаются только по60%, обычная плата сохраняется. Нельзя требовать достроить весь объект для отмены или удалить active project refs без закрытия.

У legacy/save без достоверной per-building истории нельзя выдумывать refund по нынешнему каталогу. Реализовать проверяемую миграцию, либо сохранить legacy-режим и понятно ограничить новую операцию для неизвестной истории; перечислить это в compatibility report. Prepared initial building может иметь явно заданные реальные вложения или zero-investment provenance, но отсутствие данных не равно нулю автоматически.

## 5. Уточнения реализации D

**D1/D2 промежуточны.** До D3 новый профиль ещё не содержит полного bootstrap/импорта/контента. Для доказательства механизмов допустимы честные prepared integration fixtures с зданиями/материалами/XP; это не бесплатный старт ordinary партии и не динамическое доказательство достижимости. D1 не открывает всем пять цехов; D2 открывает/строит только оплаченные и оснащённые места. D3 завершает действительную новую партию без предприятия, с200монетами и ручным cash0 recovery.

**Цехи.** Каждый имеет стабильный ID, recipe/version, enabled/reason, свой pinned WIP/прогресс/выходной hold и назначенный numeric staff. Общий конечный input/output предприятия; ни один worker/headcount не считается одновременно в нескольких workplaces. Существующая группа или несколько групп — выбрать одну непротиворечивую схему, описать payroll/голоса/наём/перераспределение. Переназначение не создаёт людей, не возвращает зарплату и не эксплуатирует старый roster в двух фазах.

0/1/2/3/4/5→0/25/45/65/85/100%; рекомендуемая единица работы basis points. Цель партии T×10000, целый progress и service remainder; сервис0.02монеты за эквивалент full-staff tick, не дважды за wall tick и progress. Зарплата только реальным работающим людям. Совместные дефициты стартов распределяются воспроизводимо без постоянного первого ID. Legacy линейная кривая сохраняется для старого профиля.

**XP/задания.** Ключ(owner,industry), суммарный опыт от реального выпуска и завершённых заданий. Одна партия даётXP только после выхода продукции, один quest/contract ID — одну награду. Shared отрасль нескольких фабрик, никаких обязательных productionCount gates; купленный товар может закрыть задание. Добыча и простая перепродажа без задания XP не дают. Два активных слота на участника в сумме, refresh1200,50/100/200/500XP,5/15/30/60базовых партий; крупному проекту минимум3600тиков. Награда только по подтверждённой фактической поставке/расчёту, не публикации объявления. Конечный спрос/деньги проекта обязательны, его нельзя выдумывать вторым бесконечным покупателем.

Техническая политика генерации: отдельный seeded stream, слоты/nextRefresh/одноразовые достижения/accepted terms/deadline/прогресс/dedup в checkpoint; refresh не меняет уже принятое задание и не перезачитывает прошлые продажи. Один и тот же fulfillment не закрывает несколько активных заданий скрыто; назначение конкретному quest фиксируется. Производственный XP и награда одного задания за тот же товар законно суммируются. Если доступного спроса нет, объяснить пустой слот вместо невозможного задания.

**Проекты.** XP открывает право, а не готовое оснащение. I..V:0/600/3000/12000/40000XP,1/3/4/5/6клеток,1..5максимальных цехов,80/120/160/200/240вход и выход. Начальный рабочий цех включён, остальные места пустые до отдельного монтажа60тиков. Земля новых клеток оплачивается, материалы во встроенном input; никакого подвоза на новую клетку. Покупка/резерв/commit/завершение атомарны и переживают load/cancel. Обычный полный проект модернизирует затронутые клетки до target Lcell; ledger сохраняет конкретный список/затраты, старые не меняются бесплатно.

Контур2×3 из MapLayout/эквивалентная проверенная legacy-схема, защита соседних прав/коридора/доступа. После начала стройки фиксируется право будущего выкупа остальных клеток именно этого предприятия, не бесплатное владение. Освобождение после отмены/сноса; пустая бронь имеет прежний TTL. Отдельный проект не поглощает соседний бизнес. D2 обновляет C2 для расширенного footprint/вложений/персонала.

**D3.** Шесть отраслей и23V1 из данных, автоматические CONTENT_TABLES; локальные recipe V2/V3 после уровнейIV/V и оплаченного оснащения. Точные производные4I→5Q/ceil(9T/2) и2I→3Q/ceil(5T/2). Это отсутствующий runtime-потребитель P63, без которого нельзя объявить все отрасли доступными. Продажа с реальным stock/payment/path/competition, не бесконечная кнопка AddStock.

Подвижная добывающая техника из§7 также не потеряна: в D3 явно активировать поддерживаемые реальные малую/большую и resource types, с числовыми группами/режимами/сохранением, либо оставить P63 частичным с точным остатком.
