## Контракт B1

Один человек + 3–10 NPC, default3, всего4–11. Число фиксировано на всю партию. Общий C# resolver в Hosting разрешает настройки новой игры в ScenarioDefinition и конфигурацию контроллеров; Godot и проверки используют его. Python может подготавливать исследовательский ввод, но не определяет новые игровые правила.

В ordinary new-game валидаторе отклонять 2/11/дроби/неверный тип, не обрезать молча. Не вводить этот предел в общий Core validator для исторических fixtures и лаборатории. У каждого NPC собственные настройки, память, PRNG, деньги/инвентарь и обычные команды. Повторяющийся skin допустим, одинаковые ID/перепутанные кошельки/совместная mutable память — ошибка. 11 экономических участников не требуют одиннадцатой уникальной модели.

Для legacy-профиля сохранить результат обычной партии с default3 там, где новый выбор ничего не меняет. Для N=4..11 масштабировать только явно перечисленные стартовые агрегаты: население и конечный предел населения пропорционально N/4, казну и стартовый бюджет столицы аналогично с точным целочисленным округлением вверх; записать базу и формулу. Не умножать личные200 монет/ёмкость на число участников. Согласованный баланс B1 задаёт20/60 населения на участника; у другого выбранного профиля используются его значения, не скрытые B1-константы. Обновление спроса/импорта происходит только при наличии активного поддерживаемого механизма из A2, не как тайная новая функция B1. Сам масштабированный агрегат не доказывает баланс на10 NPC.

Места — уникальные проходимые клетки, доступ к исходному сырью/торговле, seeded-ротация с отдельным startup RNG, не расходующим runtime PRNG. На старых картах при нехватке четырёх записанных точек добавить разрешённый пул при подготовке новой партии без сдвига старых координат/изменения старого сохранения. Промышленные клетки не дарить. Новый seed может менять назначение, но не геометрию. Для новых карт B2 использовать ровно11 заданных spawn_cells.

Настройки новой партии сохраняются вместе с разрешёнными участниками/контроллерами и нужными provenance полями. Load не строит состав заново из UI. Если прежний save уже содержит всё необходимое, вывести производные параметры без искусственного schema bump; при новом обязательном authoritative поле версионировать и проверять совместимость сразу.

## Контракт B2

| Свойство | small_river | large_districts |
| --- | ---: | ---: |
| Размер | 64×48 | 128×96 |
| Промышленные контуры2×3 | 48 | 96 |
| Ресурсные районы | 8 | 24 |
| Виды сырья | 8 | 8 |
| Лавочки / spawn_cells | 15 / 11 | 15 / 11 |
| Осевые / corridor клетки | 720 / 1872 | 2880 / 7488 |
| Стартовая городская грунтовка | 327 | 1163 |

Источник геометрии: `maps/small_river.json` и `maps/large_districts.json` внутри docs/vnext; SVG/PNG — иллюстрации этих данных, не runtime. Точные counts — проверки поставляемых карт, не ограничения универсального reader. Не добавлять воду из названия «Речные кварталы».

Нужен C# loader/адаптер в текущие ScenarioDefinition/Plots/ResourceNodes, либо воспроизводимое извлечение runtime JSON и обязательная C#-проверка. Статический Python-преобразователь не заменяет проверки Core. Ссылки на исходник, hash и resolved scenario фиксируются. Геометрия и стабильные ID одинаковы для всех чисел ботов.

Восемь ресурсов: wood/grain/stone/iron_ore/copper_ore/sand/beet/milk; public_cells — общий доступ, остальные ресурсные клетки покупаются/арендуются существующими командами. Никакой бесплатной земли. Параметры из поддерживаемого профиля A2; зерно/свёкла — поля, молоко — ферма, остальные — соответствующие лес/карьеры. Защищённый коридор не продаётся и не попадает в промышленный footprint. Контуры/entry сохраняются как явные данные для будущего расширения D; B2 не реализует покупку всех клеток/новые пять уровней задним числом.

Город: ратуша3×3 с видимым зданием2×2, терминал2×3, автосалон5×5 рядом. Непродаваемые территории, корректные входы/подъезды/коллизии. Ратуша/терминал используют существующие функции; автосалон пока отображает место будущего магазина и честную справку, не продаёт фиктивные машины. Транспорт/пополнение/дороги/тарифы — E. Стартовая грунтовка городская; если старый Core не моделирует собственника дорожной ступени, хранить геометрию/назначение города как метаданные, не обещать готовую систему вкладов.

Проверка путей учитывает реальное препятствие/ворота, не только непрерывную линию в SVG. Каждая из11 spawn-точек достигает терминала, лавочек, публичного источника каждого сырья, входа каждого промышленного контура. Существующий truck/carrier использует общий pathfinder; будущие дорожные полосы не имитируются телепортацией. Измерить длины min/median/max и перекос начальных назначений; не заявлять равенство, если оно не измерено. Нулевой кошелёк должен допускать обычную ручную добычу/продажу без платы за вход.

Внешние материалы не все производятся до D: совместимость карты с supported subset не означает, что новые отрасли уже доступны. В отчёте B2 отдельно геометрия, ресурсы/доступ, UI, текущая экономика и зависимые механики. Полный P68 закрывается только в фактически проверенной части при сохранении видимых зависимостей.

## Проверки и результат

B1: все значения3..10 проходят setup, 2/11 и неверные типы отвергаются; минимум3/6/10 реальных session smoke, труд/торговля/выборы на11 участниках, direct load/replay и own/bilateral privacy. B2: обе карты×3/6/10, дополнительно9seeds стартового назначения, topological проверки всех входов, ресурсы/перевозка/нулевой cash и native Godot preview/start/continue. На старых пяти картах минимум setup3/6/10 и legacy regression; не заменять их новыми.

Производительность — фактические step/p95, build/render startup, память/размер checkpoint, bounded pilot. Не превращать эти короткие проверки в доказательство20–35 часов развития. Windows/Android hardware, живая LLM и открытые P53/P56/P59/P60 не закрываются автоматически. API модели не нужен для алгоритмической партии.
