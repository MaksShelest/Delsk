# Codex: C2 — подготовка к сносу и возврат вложений

Запускать после проверенного C1, из основы с его кодом и этим документом. Скопируйте блок полностью.

```text
Реализуй в MaksShelest/Delsk только C2: фактические вложения предприятия,
подготовку к сносу, безопасный снос и возврат материалов на собственную землю.

1. Прочитай актуальные AGENTS/архитектуру/решения, весь
   docs/vnext/PACKAGE_CD_IMPLEMENTATION_GUIDE.md, спецификацию0.6 §5/6/13,
   план/typed баланс/mapping и фактический отчёт C1 вместе с A2/B1/B2.
   Проверь Git/HEAD/status/diff/remote/PR; основа feat/economic-cycle-p00-p05.
   C1 должен реально присутствовать (ground/overflow/projects/save),
   не только иметь промпт. Если не включён — укажи недостающую основу,
   не скрывай весь C1 внутри C2. Если часть C2 готова, заверши её.
   Отдельная ветка, существующую работу сохранить.

2. Переиспользуй ground/overflow/warehouse investment ledger из C1,
   Build/UpgradeBuilding/Logistics/equipment/groups/contracts/Checkpoint.
   Веди per-building/per-cell фактические материальные вложения, Lcell,
   provenance и отдельные съёмные активы. Все реальные успешные расходы
   записываются одновременно с transaction; неуспешная команда не оставляет
   вложение. Разделяй корпус/оснащение, оплаченные материалы и денежную
   услугу. Глобальный ConstructionInput не является историей предприятия.
   Цена/рецепт в config после покупки не изменяют фактический возврат.

3. Стоимость сноса в монетах:
   30*N +15*sum(max(0,Lcell-1)); checked перевод в minor.
   N — реально занятые клетки, не весь будущий контур. Примеры:
   начальная1xL1=30; двеL2=90. При разном Lcell считать каждую клетку.
   Проверяй только свободные деньги, holds/escrow не тратить.
   Цена/возврат в preview и commit проверяются по одному актуальному
   состоянию; stale quote не списывает другую сумму без нового согласия.

4. Возврат строительных материалов по каждому ItemId:
   floor(60% * SUM(фактических вложений этого товара)). Один floor после
   суммы, не по отдельным записям.30wood->18,3steel->1; три записи1steel
   суммарно также дают1, а не0. Денежная оплата не возвращается.
   Существующие input/output/free normal stock возвращаются100%,
   не60%; overflow сохраняет прежний expiresTick, не получает новый срок.
   Съёмное оборудование сохраняется целиком ровно один раз. Если предмет
   снят как оборудование, он не входит второй раз в стройвозврат.
   Нормативная денежная цена оборудования не превращается в новый предмет.

5. Немедленный снос блокируется на реальных обязательствах: WIP,
   активный project/входящая или исходящая поставка/рейс/physical груз,
   чужие права pickup, stock/capacity/cash holds, незавершённая ручная
   transfer и прочие refs, которым объект ещё нужен. Исследуй полный
   reverse-reference граф, не проверяй только Enabled=false.
   Свой выключенный route с пустым рейсом безопасно отсоединяется либо
   требует явного отключения; нельзя оставить висячий reference послесноса.

6. Команда «Подготовить к сносу» ставит ясное persisted состояние:
   запрещает новые партии/новые контракты/рейсы/публикации от объекта,
   но начатое производство может завершиться и начатый транспорт доехать/
   вернуться. Не используй Stop, который навечно замораживает WIP.
   Владелец может внести необходимые деньги/сырьё для завершения и вывезти
   запасы; нехватка средств объясняется, не списывается чужой резерв.
   Не отменяй подписанный договор и не телепортируй груз. Отмена подготовки
   не возвращает уже сделанные операции и не включает новые работы скрыто;
   возобновление через обычные явные switches. Для начатой стройки/апгрейда
   C1 добавь явное прекращение проекта на безопасной границе с последующим
   C2 подтверждением сноса незавершённого объекта/части: снять только
   неиспользованные holds, сохранить фактически потраченные вложения,
   применить обычную плату и60%recovery, не полный refund. Действующий
   project сначала безопасно закрывается, его refs не удаляются скрыто.
   Quote учитывает реальный occupied footprint и сохранённые Lcell;
   нельзя заставлять игрока достраивать весь объект ради отмены.
   Все причины запрета видны
   владельцу, чужие private terms публично не выдаются.

7. Финальный commit атомарен: повторно валидировать ownership/quote/
   blockers/средства/overflow destination, списать цену, получить stock и
   recovery, освободить footprint/коллизии/группы/refs, сохранить землю.
   Персонал возвращается в unemployed с сохранением общей population;
   зарплатные остатки/holds/голоса не висят и не дублируются. XP отрасли
   после его появления D2 остаётся у владельца, не у удалённого здания.
   Материалы распределить стабильным порядком освобождённых клеток,
   до70normal объёма каждой; разрешённый остаток — C1 overflow1200.
   Не телепортируй в далёкий склад/рюкзак. Перенесённый старый overflow
   срока не обновляет. C1 ledger/recovery flows/capital учитывают возврат
   один раз, gross ConstructionInput остаётся историей расхода.
   Реальный товар/cargo/оборудование не исчезает при удалении сущности.

8. Legacy compatibility: нет достоверной per-building истории — нельзя
   вычислить refund по сегодняшнему справочнику. Реализуй доказуемую
   миграцию либо сохрани legacy-режим с ясным ограничением новой операции.
   В отчёте перечисли affected saves/fixtures. Prepared initial building
   имеет явный zero-investment provenance или заданные реальные вложения;
   missing ledger не приравнивай молча к0. Старые файлы не удалять/не
   перезаписывать. Новые поля в DTO/hash/replay/validators/exports сразу.

9. UI RU/EN: управление->снос->стоимость/материалы/предупреждение->
   удержание подтверждения2секунды. Снос не рядом с часто нажимаемым
   Start без защиты. Удержание — только UX, Core всегда повторно проверяет.
   Cancel/escape/закрытие/потеря focus не сносят и не списывают денег.
   Preview разрешённых возвратов/фактического normal+overflow и объяснение
   blockers. Native проверка настоящих clicks/hold/cancel, без fake stock.
   NPC могут подготовить/снести той же командой в контролируемом сценарии;
   полноценную стратегию переноса бизнеса оставить G.

10. Тесты: точные30/90, mixedLcell,60%aggregate floor, обновление config
    после вложения,100%stock, съёмный актив без duplicate; overflow сверх
    всех70, сохранение старого срока; деньги insufficient/reserved,
    чужой объект/civic/земля, двойной confirm/повтор command/stale quote;
    все blockers включая pickup/route/loaded return/WIP/project/transfer;
    prepare drain/нужное пополнение/cancel; abort начатой стройки без полного
    refund/висячих refs; работники/голоса/population;
    товарные и денежные равенства/capital/recovery/sink.
    Checkpoint до подтверждения/во время подготовки/после сноса/передexpiry:
    continuous/directload/replay совпадают. Нельзя готовить тест удалением

Прогони общие gates из guide: Core/headless/Developer/A1/A2/B1/B2/legacy,
native RU/EN/узкое окно. Прежний default профиль/семь карт не подменяй.
Без цехов/XP/нового импорта/расширений D и без машин/услуг E/F.
Отчёт docs/IMPLEMENTATION_REPORT_PACKAGE_C2.md, compatibility/usage/evidence,

Отдельный commit/PR, без автоматического слияния. После C2 остановись
перед D1; следующую итерацию автоматически не выполнять.
```
