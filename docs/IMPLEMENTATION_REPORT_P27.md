## Что можно настраивать самостоятельно

Единый источник обычного игрового баланса — [config/economy.json](../config/economy.json). Раздел world содержит деньги, цены, население/найм, производство/материалы/энергию, технику, логистику, торговые сроки/штрафы, спрос, выборы и отдельные параметры формул. Раздел npc содержит экономические параметры и веса решений ботов. Шаг зарплаты человека и повышение ботами вынесены из кода. Нового разового платежа за найм не введено: существующая модель оплачивает численность по ставке за работу.

Runner принимает `--economy`, `--validate-only true`, `--profile true`; Godot использует тот же загрузчик и профиль для двух игровых карт. При экспорте есть встроенная копия, внешний вариант передаётся аргументом. Конфигурация разрешается перед стартом, входит в Core hash/save, настройки NPC сохраняются в controller state. Загрузка/replay не принимают новый профиль вместо исходного. Неизвестные/дублированные ключи и неверные значения отклоняются; плохой баланс опыта не подменяется исходным автоматически.

Фиксированные целевые показатели исторических baseline-сценариев не применяются к явно заданному исследовательскому профилю: дорогая земля и нулевой выпуск могут быть корректным результатом. Инварианты денег, товара, численности, holds и прав остаются обязательными. В gate есть отдельный CLI-опыт с недоступно дорогой землёй, проверкой нулевых предприятий и точного save/load.

Для пользователя: [подробное руководство, таблица параметров и команды](ECONOMY_CONFIGURATION.md). `scripts/run_economy_study.py` делает точные копии входов/SHA-256 и одинаковые семена A/B, запускает C# с timeout, выдаёт comparison.csv/study.json. Python не рассчитывает экономику.

## Завершение P26.6 C

На двух обычных картах торговых мест ровно по числу участников. Они не назначены участникам заранее; покупка и бронь проходят общий Core-лимит одно owned-or-reserved в сумме. Переход своей брони в собственность разрешён. Отмена освобождает выбор без возврата платы. Нельзя строить производство на месте лавки. NPC выбирает доступное место с учётом собственной собственности/брони и расстояния, общий валидатор решает конкуренцию. Legacy assigned slots сохранены только в исторических фикстурах.

Планшет рынка участников открывается на реальной лавке или отдельно в столичной зоне. Есть публичные лоты/цены/координаты/раунды/таймер, фильтр товара и оба порядка цены, количество/максимальная цена, подача/повышение/отзыв заявки, собственные результаты и физическое получение товара на месте с учётом рюкзака/срока. В своей лавке — понятные передача в/из рюкзака и публикация реального свободного запаса. На паузе команды ждут обычного тика. RU/EN, закрытие по выходу из доступной области, общая тактическая пауза и независимые menu/focus причины сохранены. Исправлен выявленный оконной проверкой случай изменения количества получения на паузе: команда читает текущее поле, а не старое значение при построении строки.

PublicShops показывает только ID/владельца/географию. PlayerMarketView использует Observe: публичные условия, только собственные ставки/лимиты и свои/двусторонние распределения. Чужие запасы, счета, закрытые лимиты и поддержка не добавлены. Будущие поставочные контракты остаются отдельным Core/runner механизмом и не смешаны с получением купленного лота.

## Версии и сохранения

World13 / Rules research-economy-1 / Session2 / Envelope2. Новое поле IsShopSite проверяется при конфигурации и restore, quota — также живыми инвариантами. Балансовые правила и профиль ID входят в разрешённую конфигурацию. Старые World12/manual-harvest-1 saves не мигрируются и остаются на прежнем пути, нужна новая партия. Policy utility-economy-v2/checkpoint2 сохраняет дополнительный WageRaiseMinor; прежний мир отвергается по World/Rules.

P27 измерил37,823,935 байт старого несжатого формата после1200 тиков. Новый Envelope2 использует GZip+base64 с checksum, лимитом64MiB файла и512MiB распакованного payload, проверкой JSON/ссылок/инвариантов/hash. Все решения/наблюдения/журнал сохранены, история не обрезана. Envelope1 текущей World/Rules читается для проверки совместимости контейнера; это не миграция старых правил. Atomic temporary/backup и проверка перед установкой файла сохранены.

Первый длинный замер превысил первоначальный распакованный лимит256MiB; после проверки реального объёма истории он заменён явным512MiB. Повтор5000 тиков прошёл. Данные ниже относятся к удачному повтору; неудачный запуск не выдаётся за pass.

## Итог первого месяца

Core, алгоритмические NPC, необязательный LLM-адаптер, исследования, технический клиент, управляемая 3D-презентация A/B/C и итоговый пакет проверок реализованы. Можно самостоятельно менять экономику и проводить воспроизводимые headless-опыты; отдельный промпт Cursor/Codex для этого не нужен.

Открыты готовый Windows EXE на устройстве, Android lifecycle/эргономика/память/производительность и новая живая демонстрация Gate D текущей сборки. История длинной партии имеет измеренное ограничение выше. Поэтому месячный **программный объём** готов, полная приёмка месяца/P27 остаётся условной до фактических локальных результатов. Следующий шаг — локальная приёмка по приложенной инструкции и затем ограниченная работа второго месяца с учётом измерений, без объявления hardware/LLM pass по fake или Linux-рендереру.
